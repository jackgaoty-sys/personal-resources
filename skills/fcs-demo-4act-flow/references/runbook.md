# 现场操作单（Runbook）

> 打印或放在第二屏。演练时按此走，不要临场想。
> 全部命令里的 `$FCS_DEMO` 换成实际路径。

---

## 0. 演示前 30 分钟 · 预热清单

```sh
export FCS_DEMO="/path/to/fcs-demo"    # ← 改成你的实际路径（已开发完毕的飞控系统目录）

# ① 补丁在位
node scripts/apply_aero_toggle.mjs --dir "$FCS_DEMO" --check

# ② 起服务（保持前台或 nohup，别让终端被关掉）
cd "$FCS_DEMO" && npm run dev
#   → http://localhost:5173/
```

浏览器里依次确认（**必须在观众到场前做完**）：

| # | 地址 | 确认 |
|---|---|---|
| 1 | `/?aero=1` | 能配平到平飞；顶栏"气动: 开"；3D 有地形；PFD 正常 |
| 2 | `/?aero=0` | 顶栏"气动: 关"；启动日志写"简化动力学（无气动数据）"；飞机乱飘、高度掉 |
| 3 | 按 `V`（`aero=1` 下） | 参照机出现，同框对比可见 |
| 4 | 场景预设 → "AHRS 失效 → DIRECT LAW" | 法则降级，事件日志有"法则 NORMAL → DIRECT" |
| 5 | 点"导出 CSV" | 有文件落下 |

**预热的意义**：WASM 1.5 MB + 双内核配平，冷启动要十几秒。
观众面前第一次加载卡住，是这类演示最常见的翻车点。

## 1. 分幕操作单

### 第 1 幕 · 入口（约 15 秒）

- 平台左侧导航 → AI Lab → 跳转。
- 截图：`act1-entry.png`。
- 只说一句："它进的是我们自己的平台，Agent 嵌在里面。"

### 第 2 幕 · 需求分析（约 3–5 分钟）

> 展示人对观众的解说见 `presenter-script.md` §2；**学生台词不给**（学生是真人，自由作答）。

- 学生（真人）自然说出需求（例如“我想做一个飞控系统”）——是他自己的话，不是台词。
- 平台按 `quiz-bank.md` **A 组**逐个问，**一次一个**；拿到学生回答后按 rubric 判定，再决定追问/纠偏/进下一题。
- 收在"如果只保留三条，你保留哪三条"（**学生自己总结**，平台不代答）。
- 把结论写进 `demo-artifacts/requirements.spec.md`（模板见 assets）。
- 截图：`act2-requirements.png`。

### 第 3 幕 · 阶段成果与改进（约 5–8 分钟，**全场重点**）

| 节拍 | 操作 | 讲法 | 产出 |
|---|---|---|---|
| 3.1 | 加载 `/?aero=0` | “先看第一版。界面是完整的。” 先把 PFD/ECAM/3D/日志/时间历程逐块指一遍 | `act3-aero-off-symptom.png` |
| 3.1 | 松手 10 秒不动 | “我什么都没碰。”（**沉默是设计的一部分**） | 症状可见 |
| 3.2 | 按 B 组逐条问“你看到了什么” | 一定要问到 **B8：前端全都是好的** | — |
| 3.3 | 抛 C 组选择题 | 三种演法：观众互动 / 自问自答 / 故意答错（选 D 再改 B）。**学生即展示人，答错不会自己发生** | — |
| 3.3 | 可选 D 组填空题 | D4（因果链）最值钱 | — |
| 3.4 | 切 `/?aero=1`（或点顶栏“气动”） | “我们把气动数据接进来了。”**切完先沉默 5–10 秒** | `act3-aero-on.png` |
| 3.4 | 同样松手 10 秒 | 高度稳住、姿态保持 | 对照成立 |
| 3.5 | 两版各导一份 CSV | 并排看升降率 | `act3-aero-off.csv` / `act3-aero-on.csv` |

> **3.4 是本流程的高光**：就在观众眼前从"乱飞"变"能飞"。
> 切完**不要马上说话**，让它自己飞一会儿 —— 沉默比解说更有说服力。

### 第 4 幕 · 成品试飞（约 4–6 分钟）

保持 `/?aero=1`，按下表逐条演（时间不够就砍后三条）：

| # | 操作 | 看点 |
|---|---|---|
| 1 | 正常法则平飞，松杆 | `FPA HOLD` 保持航迹 |
| 2 | 满杆拉到底 | `LOAD`/`ALPHA PROT` 介入，日志出现"保护介入" |
| 3 | 场景预设 `alpha` | α 传感器失效 → ALTN LAW |
| 4 | 场景预设 `ahrs` | AHRS 失效 → DIRECT LAW，保护丢失，飞机变"生" |
| 5 | 按 `V` | 参照机同框，"飞控到底做了什么"一目了然 |
| 6 | 导出 CSV | 收尾归档 |

截图：`act4-flight.png`、`act4-protection.png`、`act4-degraded.png`、`act4-ghost.png`。

**收尾话术**：
> "同一架飞机、同一套操纵、同一个油门 —— 差别只在有没有飞控。
> 这就是飞控系统存在的意义。"

## 2. 时间轴驱动（可选）

```sh
cd "$FCS_DEMO" && npm run dev &                        # 先起服务
node scripts/demo_driver.mjs \
  --dir "$FCS_DEMO" \
  --timeline assets/timeline.default.json \
  --out "$FCS_DEMO/../demo-artifacts"
```

接管热键（在跑驱动的终端里输入）：

| 输入 | 行为 |
|---|---|
| `Enter` | 继续 |
| `p` | 就地暂停，再 `Enter` 继续 |
| `skip` | 跳过剩余暂停点，一路跑完 |
| `next` | 跳到下一幕 |
| `q` | 退出（已产出的文件保留） |

**任何时候都可以直接在浏览器里手操**，驱动不会跟你抢状态。
如果某一拍讲得比脚本预想的长，直接 `p` 暂停，讲完再 `Enter`。

## 3. 应急

| 症状 | 原因 | 处置 |
|---|---|---|
| 页面卡在"初始化…" | WASM 未加载完 / 端口被占 | 等 20 秒；`lsof -i :5173` 杀掉占用；换端口 `npm run dev -- --port 5174` |
| 3D 是一片纯色/灰地 | 外网断了（Esri 影像 / AWS 高程拿不到） | **主动说明**："地形底图需要联网，已自动降级为程序化地面，不影响飞行。" 然后照常演示 |
| `?aero=0` 下飞机很快坠毁弹出"坠毁"遮罩 | 下沉累积（约 2 分钟到底，若中途加速过） | 这是**合法症状**，可顺势讲"没有升力，最后就是这个下场"。按 `R` 或切回 `?aero=1` |
| `?aero=1` 下开场就乱飞 | 补丁没生效/被回滚 | 跑 `--check`；必要时 `--revert` 后再打 |
| 顶栏没有"气动"按钮 | `index.html` 补丁未生效 | `--check` 会报出哪一处缺失 |
| 事件日志写"JSBSim 内核装载完成"但 `aero=0` | 启动日志补丁未生效（**会导致教学逻辑自相矛盾**） | 立刻补，别带病上场 |
| 断言在某步报错 | 状态没到预期 | 不中断，继续。事后看 `run.log` |
| 现场时间不够 | — | 输入 `skip` 跑完剩余；或砍第 4 幕后三条展示项 |

---

## 4. 演示的"三条红线"

1. **不要**在 `?aero=0` 下说"这是我们的最终产品"。它是阶段版，是道具。
2. **不要**跳过 B8（前端全是好的）。跳过就变成"看笑话"了。
3. **不要**在 3.4 切完之后立刻长篇解说。让飞机自己飞，比任何解说都有力。
