# 引导题库（第 2 幕）与排障题组（第 3 幕）

> **角色说明：剧本里的“学生”就是展示人本人。**
> 因此 A 组的问题是**平台问、展示人答**——展示人的现成答话在
> `presenter-script.md` §2.2；本文件只负责“题目该问什么、落点在哪”。
> B/C/D 组同理：题面与正确答案依据在本文件，现场怎么开口看 `presenter-script.md`。
>
> 用法：**一次只问一个**，等对方答完再追问。
> 题目的落点必须收敛到 fcs-demo 已有的能力上（见 `fcs-demo-contract.md` §4/§5/§7），
> 否则第 4 幕兑现不了 —— 这是本题库最大的约束。

## A 组 · 第 2 幕：需求分析引导

目标：让"我想做个飞控系统"变成一份**可验收**的需求规格（`requirements.spec.md`）。

| # | 问题 | 期望落点（必须是 fcs-demo 能做的） |
|---|---|---|
| A1 | 飞控"控"的是什么量？先说三个。 | 俯仰/滚转/偏航三通道的姿态与角速率 |
| A2 | 飞行员给的是"意图"还是"舵面角度"？ | 意图。飞控夹在侧杆与舵面之间，算舵面指令 |
| A3 | 松杆之后飞机该怎么办？ | 保持当时航迹（`FPA HOLD`）、保持坡度（`BANK HOLD`） |
| A4 | 如果飞行员想把飞机拉到失速，你允许吗？ | 不允许。要有迎角保护（`alphaProt 12°` / 硬上限 `15°`） |
| A5 | 过载和坡度的边界划在哪？ | 载荷 `-1.0 ~ 2.5 g`（结构上限 3.8）、坡度 `55°` 并回退到 `30°` |
| A6 | 传感器坏了怎么办？ | 降级而不是停机：`alpha_sensor`→ALTN，`ahrs`→DIRECT |
| A7 | 降级之后能自己恢复吗？ | **不能**（法则只能变差）。这是安全设计，不是缺陷 |
| A8 | 作动器卡住/变慢呢？ | 作动器降级（权限 35%）、卡阻（卡在上一位置） |
| A9 | 你怎么向飞行员证明你在工作？ | 显示：PFD 姿态/速度/高度、ECAM、模式与保护状态、分级事件日志 |
| A10 | 怎么证明"飞控真的影响了飞行"，而不是个装饰？ | **对照实验**：同一杆位油门，有增稳 vs 无增稳（参照机），比轨迹 |
| A11 | 数据要留痕吗？ | 时间历程录制（60 Hz）+ CSV 导出，用于事后复查 |
| A12 | 严重的结构损伤之后呢？ | 真接进飞行：`DAMAGE_AUTH` 衰减舵面权限与作动速率，飞机会变"笨" |

**收尾问句**（把需求钉死）：
> "如果只保留三条，你保留哪三条？"
> 参考答案：① 三通道增稳；② 包线保护（迎角/载荷/坡度）；③ 故障后降级不失效。
> 这三条正好覆盖 fcs-demo 的三个亮点，第 4 幕逐条演。

### 产出：`requirements.spec.md`

用 `assets/requirements.spec.template.md` 起头，必须包含：**指标要可测**
（例如"迎角不得超过 15°"，而不是"要安全"）。可测性是第 4 幕验收的钩子。

## B 组 · 第 3 幕 3.2：症状清单（引导学生"说出看到了什么"）

不要直接说结论。挨条问"你看到了什么"，把症状说完再进 3.3。

| # | 看哪里 | 应该看到的（实测） | 说明什么 |
|---|---|---|---|
| B1 | 3D 视景 / PFD | **手不碰杆，坡度自己摆到 ±18°**（峰峰约 36°）；俯仰缓慢漂移约 5° | 没有静稳定性、没有气动阻尼 |
| B2 | PFD 升降率 / 高度 | 升降率一路为负（约 **-1680 fpm**），高度单调下降 | **没有升力**抵消重力 |
| B3 | 拉杆到底 | 高度**照样掉**，而且姿态会翻过去（θ → **180°**） | 推力在垂向只有 sinθ 分量，压不住重力 |
| B4 | 配平（`pitch-trim-cmd-norm`） | 拨了没有任何效果 | 没有气动就没有配平平衡点 |
| B5 | 迎角 α | 在 **-4.5° ~ 10.3°** 之间缓摆，与姿态/操纵对不上 | 迎角不是气流解出来的，是合成量 |
| B6 | 过载 nz | 恒为 **1.04 g**，拉满杆也不涨 | 过载与操纵无关 |
| B7 | 顶栏保护提示 | 松手不亮；**拉满杆会亮 `LOAD` + `PITCH`，压杆会亮 `BANK` —— 但飞机完全不理会**（θ 照翻、高度照掉） | 保护算对了，却没有可作用的对象 |
| B8 | PFD / ECAM / 3D / 事件日志 / 时间历程 | **全部正常渲染** | 前端是好的 —— 坏的只有动力学 |
| B9 | 事件日志第一行 | "系统就绪：简化动力学（无气动数据）" | 系统自己承认缺了什么 |

**B8 必须被点出来**。不点的话，观众会得出"整个演示是坏的"，
而正确的结论是"**前端全对、模型缺了一块**"——这才是第 3 幕要教的工程判断。

> **B7 的讲法很重要**：不要说"保护失灵了"。保护其实**算对了、也播报了**，
> 只是过载和迎角不再由操纵产生，保护没有可作用的物理对象 ——
> 这正是下面 C 组迷惑项 D 的解说，也是 B7 与 C 组最关键的呼应点。

## C 组 · 第 3 幕 3.3：选择题

**题面**：
> 飞机能飞起来、能稳定，靠的是空气流过机翼产生的力。
> 现在这个版本"没有空气动力学模拟"。要让飞控真正影响飞行，
> 我们必须补上的是哪一块？

| 选项 | 内容 | 判定 |
|---|---|---|
| A | 把 3D 模型换得更逼真（更好的飞机模型/贴图） | ✗ 只影响观感，不影响飞行 |
| B | **气动力矩的计算：气流→机翼→力与力矩（外加承载它的 6-DoF 运动方程）** | ✓ 正确 |
| C | 把界面刷新率提高到 144 Hz | ✗ 显示更流畅，飞机照样乱飞 |
| D | 增加更多的保护逻辑（把迎角上限调得更严） | ✗ 作用在错误的对象上：没有气动，过载和迎角根本不由操纵产生，保护无从触发 |

正确答案 **B**。

> **现场怎么把这道题“问出张力”**：学生就是展示人，所以“答错→被纠正”不会自己发生。
> 三种演法（详见 `presenter-script.md` §3.3）：
> (a) 观众互动——把选项投出来让观众选，展示人再把答案说给平台；
> (b) 自问自答——直接答 B；
> (c) 故意答错——先答 D，等平台指出问题后再改口选 B（教学最足，多花约 1 分钟）。

**为什么 D 是迷惑项**（这是本题的教学价值）：
保护是**架在气动之上**的。气动没了，迎角与过载就不再是"操纵的后果"，
保护没有可作用的对象 —— 这也正好解释了 B7（保护永远不介入）。
**先有对象，才谈得上保护**。

## D 组 · 第 3 幕：填空题（挑一道，看时间）

**D1（数据）**
> 把 ______ 的气动力/发动机数据表交给 6-DoF 内核，飞机才知道"机翼在什么迎角下产生多少升力"。

参考答案：机型（本演示为 `c172p`）。对应实物：`public/data/aircraft/c172p/c172p.xml`。

**D2（内核）**
> 承载气动力矩并积分成运动的那一层叫 ______。

参考答案：飞行动力学模型 / FDM（本演示为 JSBSim，编译成 WASM 跑在浏览器里）。

**D3（闭环）**
> 本项目的飞控在每一帧里做了三件事：读飞行状态 → 算 ______ → 写回舵面指令。

参考答案：舵面指令（写进 `fcs/*-cmd-norm` 通道）。

**D4（因果链，最值得问）**
> 补上气动之后，"拉杆"这条因果链变成了：
> 拉杆 → 飞控算出舵面指令 → 舵面偏转 → ______ → 飞机响应。

参考答案：气动力矩（升力增加 → 抬头力矩 → 迎角/姿态改变）。
D4 答对说明学生理解了**闭环**，可以直接进 3.4。

## E 组 · 第 3 幕 3.5：收口问句

用来把"修好了"从感觉变成证据：

1. "你怎么证明现在是真在飞？" → 高度不再单调下降、松杆姿态能保持、拉杆能改变航迹。
2. "跟刚才那版比，同一个动作差在哪？" → 用导出的两份 CSV 并排看。
3. "参照机（按 `V`）是什么？" → 同杆位同油门、去掉增稳与保护的对照机。
   **它等于刚才的 `?aero=0`，但气动是好的** —— 于是"缺气动"与"缺增稳"
   这两件事被彻底分开了。这一问能把整幕的因果讲干净。
