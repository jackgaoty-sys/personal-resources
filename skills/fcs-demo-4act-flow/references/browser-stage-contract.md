# 内部浏览器展示契约

本文件约束演示的可见载体。目标是让领导和教师始终在同一个平台界面中看到模型理解、生成、检索、诊断和验证的全过程。

## 唯一展示窗口

- 使用 Codar/平台内部浏览器展示所有网页和应用。
- 不打开系统默认浏览器，不启动独立 Chromium/Playwright 窗口，不把终端当作展示画面。
- 同一阶段尽量复用一个内部浏览器标签页；确需对照时最多保留两个标签页。
- 浏览器必须对现场可见，后台页面不算完成展示。

## 准备与展示必须隔离

- Skill 加载、依赖检查和后端启动期间，不得创建或导航现场内部浏览器标签页；允许使用执行完即销毁的独立无界面浏览器预热。
- “所有重要内容通过内部浏览器展示”只适用于状态机已经放行的正式展示，不允许把预热伪装成展示。
- 禁止用内部浏览器隐藏标签、最小化窗口、提前打开再切回等方式预载演示页面；这些页面可能被界面自动聚焦或恢复。预热只能由 `scripts/prewarm.mjs` 在隔离的 headless 会话中完成。
- 正式演示前，内部浏览器只能停留在平台入口或空白页。
- 每个页面只能在对应状态第一次导航：需求规格在 S4，无气动阶段版在 S5，CNAI4S 与下载卡片在 S7，完整气动版在 S7 修正完成后。
- 若发现某个后续页面已提前出现，必须关闭该标签并回到当前状态；不得把它解释成预览后继续演。

## 各幕展示载体

| 内容 | 展示位置 |
|---|---|
| 师生问答 | 当前对话界面 |
| 结构化需求规格 | 内部浏览器中的文档预览页 |
| 第一版/无气动阶段成果 | 内部浏览器中的飞控应用 |
| CNAI4S 外部数据源 | 内部浏览器中的真实站点页面 |
| 模拟资源下载 | 内部浏览器中的 `assets/aero-resource-download-card.html` |
| 修正后与最终产品 | 内部浏览器中的飞控应用 |
| 对比数据或验收结果 | 内部浏览器中的表格/报告预览页 |

对话区只保留必要的一句话说明或一个问题。不要把完整规格、诊断报告、资源列表或验收表直接堆在聊天回复里。

排练阶段可以确认 `assets/aero-resource-download-card.html` 能通过平台内部文件预览或本地 HTTP 服务打开，但排练结束必须关闭标签页并恢复平台入口。正式演示加载 Skill 时只能做文件存在性和 HTML 解析检查，不得为验证而提前打开该页面。

## 页面切换要求

- 每次导航后先确认页面标题或关键内容已经可见，再解说。
- 切换页面时用一句短播报交代模型当前动作，不暴露 URL 参数、文件路径或幕后状态名。
- 外部站点页面只陈述现场真实可见的信息。
- 本地演示卡片必须清楚表达“资源获取完成”，但不得生成真实下载，也不得声称外部站点提供了页面上没有的具体文件。
- 返回飞控应用后才允许展示气动修正结果。

## 失败处理

- 内部浏览器打不开页面：停在当前步骤，不用聊天文字代替网页展示。
- 外部站点临时不可用：使用事先准备并明确标记的缓存页面；没有缓存就中止这一节拍。
- 模拟下载卡片打不开：不得口头声称下载完成。
- 修正后的应用未显示：不得进入最终试飞。
