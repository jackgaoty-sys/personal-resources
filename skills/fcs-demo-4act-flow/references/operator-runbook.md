# 操作手册（内部）

本文件只供模型操作演示应用。不得把地址参数、内部开关、文件名、断言、准备命令或预制机制告诉现场。

## 正式演示环境的界面要求

Skill 只能约束 Agent 生成的文本，不能保证关闭承载平台自动绘制的推理摘要、工具事件或执行详情。正式演示前，操作人员必须完成一次非公开排练，并按当前平台能力执行以下任一方案：

1. 隐藏或折叠执行详情、推理摘要和命令输出；
2. 若平台不能隐藏，只向观众投放对话区与内部浏览器等演示内容区域，过程面板保留在操作端；
3. 若以上均不可行，不得使用该承载环境进行正式现场演示。

本 Skill 不写入任何 Agent 或平台的专用配置，也不假设固定产品、客户端或配置文件。即使宿主已隐藏过程面板，Agent 仍须遵守 `SKILL.md` 的全通道保密防火墙，因为进度文字、工具标题和错误消息仍可能独立可见。

## 准备

复用本 Skill 中已经准备好的 `fcs-demo/`、气动切换能力和运行依赖。S0 前只允许完成文件检查、端口检查、依赖安装、服务启动、补丁检查、症状回归和时间轴校验。

### 不可见预热（必须）

- 不得在内部浏览器中打开 `?aero=0`、`?aero=1` 或任何飞控应用页面。
- 不得打开需求规格、CNAI4S、模拟下载卡片或成品验收页。
- 后端就绪后运行：`node scripts/prewarm.mjs --dir "$FCS_DEMO" --base-url http://localhost:5173`。
- `prewarm.mjs` 只允许启动 `headless: true` 的独立临时浏览器，不得使用内部浏览器会话、现有浏览器标签或可见窗口。
- 预热必须覆盖 `?aero=0`、`?aero=1`、CNAI4S 任务页和模拟资源卡片；只保留本地服务编译结果、操作系统文件页缓存和网络预检结果，不保留浏览器会话缓存、浏览器进程、页面、截图、下载或标签页。
- 预热输出属于后台准备信息，不得转贴到现场对话。
- 如果之前的排练留下了演示标签页，开场前必须关闭，并恢复平台入口或空白页。
- 后端服务已启动不代表演示已经开始；禁止因为服务可访问就自动导航。

不可见预热负责消除主要的后端、构建和 WASM 冷启动等待，但隔离浏览器的页面缓存不会转移给现场内部浏览器，因此不承诺绝对零等待。预热失败时可退回静态资源预取，但仍不得用现场内部浏览器代替预热；不允许因为追求零等待而提前暴露结果。

## 页面状态映射

- 阶段状态：使用原演示的无气动状态。
- 修复状态与成品状态：使用原演示的完整气动状态。

这些映射属于幕后控制信息。现场看到的是“模型生成的阶段结果”和“模型修正后的结果”，不是查询参数、开关或代码实现。

## CNAI4S 外部数据源节拍（强制）

无气动状态与完整气动状态之间必须插入以下可见流程，全部在平台内部浏览器中完成：

1. 打开 `https://beta.cnai4s.com/`，让首页的“科学智算共性平台”和流体力学入口可见。
2. 导航到 `https://beta.cnai4s.com/science-tasks/139`。
3. 在页面中停留并让现场看到至少三项真实信息：任务名“eHDNN方法求解抖振流场”、学科领域“流体力学”、方法简介中的翼型/流场内容；页面可见时也展示“在线资源”区域。
4. 用一句执行播报说明正在提取可用于气动物理补全的流场建模资源。
5. 在内部浏览器打开 `assets/aero-resource-download-card.html`，展示模拟下载进度达到 100% 和资源清单。此卡片仅为演示状态，不产生文件，不点击网站上的真实下载入口。
6. 返回飞控应用并切换到完整气动状态。

现场口径应是“模型访问外部科学数据源，获取相关专业资源，并据此补齐气动物理能力”。不要声称 CNAI4S 直接提供了飞控应用内部的具体机型配置、JSBSim 文件或已经发生真实网络下载。

若预检时 CNAI4S 不可访问，不要在正式演示中从无气动状态直接跳到有气动状态。应在演示开始前恢复网络，或明确准备一份通过内部浏览器展示的站点缓存快照；缓存快照必须标明“缓存页面”。

## 操作原则

- 只在状态控制器允许时切换页面状态。
- 所有展示页面只在内部浏览器中打开；不得唤起系统浏览器或独立 Playwright 窗口。
- 页面操作必须真实发生；不要只用文字声称已经展示。
- 只讨论当前页面上已经可见的证据。
- 工具输出、控制台日志和内部断言不直接转贴到现场。
- 下载或导出若不是当前教学任务，不主动执行或提及。
- 页面失败时停在当前状态，不用幕后答案替代演示。

## 能力展示口径

- 规格出现时强调模型把自然语言转成了结构化、可验收需求。
- 阶段版出现时强调模型已产出一个可运行版本，不把重点放在学生掌握知识。
- 诊断时展示“读取现象—关联证据—形成结论”的推理链，但只说当前必要内容。
- 修正时可以播报正在调用专业数据或工具，但不得展示实现机关，也不得虚构不存在的实时过程。
- CNAI4S 访问和模拟资源下载是修正过程的必演步骤，不是可选解说。
- 成品试飞时用真实运行结果证明生成能力，不用长篇讲授飞控原理。

## 原有材料的使用边界

原目录中的应用代码、资源和验证脚本可以继续复用。旧版对话控制文档不再作为对话控制器；若需查技术事实，只提取当前状态必需的事实，并服从新版 `SKILL.md` 的输出边界。
