# 执行方式（硬要求）：必须"看得见地"演一遍

> **这份文件是给"平台"（Agent）看的，优先级高于本 Skill 里任何"怎么跑脚本"的说明。**
> 目的：杜绝"后台跑完脚本 → 汇报一堆产出物"这种**假演示**。

---

## 1. 一句话

**本 Skill 的交付物是"当场演一遍"，不是"脚本跑通了"。**

四幕是**教学演示**，观众要看的是"从零长出来的过程"。
把 `demo_driver.mjs --headless` 在后台跑一遍，再把 `demo-artifacts/` 列出来，
**不构成演示** —— 那是冒烟测试，观众什么都没看到。

> 驱动脚本也**没有**“跳过暂停、一路跑完”的模式（`--no-pause` 已移除）。
> 暂停点接不上真人时，脚本会**直接报错退出**，而不是替你继续。

## 2.5 触发闸门（硬约束）：没听到“飞控系统”，就不许往下走

**第 2 幕的引导问答，只有在学生用自己的话说出与“飞控系统”相关的需求之后，才可以开始。**

| 允许（后台准备） | 禁止（展示抢跑） |
|---|---|
| 提前起 dev server、装气动开关、跑症状回归、预热 WASM、校验时间轴、建产出目录、预加载页面 | 学生开口之前，**抛出 A 组任何一道题** |
| 把舞台交给学生：“你想做的东西，用一句话说说看？” | 平台**替学生说**那句需求（哪怕只是“举个例子”） |
| 触发之后：按 A 组**一次一问** | 触发之前就推进到第 3 幕 / 第 4 幕 |

**判定（平台内部，不念给学生）**：学生的输入指向“做一个飞行控制系统 / 飞控 / 飞机控制系统 /
让飞机自己保持稳定”这一类意图，即视为触发。答非所问（例如“我想做个网站”）→ 平台**引导或追问**，
不要直接进 A 组。

> **为什么卡这么死**：这一幕的教学价值全在“学生先说了什么、平台才动”。
> 平台抢跑（或替学生说），观众立刻看出是背稿，“从零长出来”就没了。

**必须分清两件事**：

- **后端准备**可以提前、可以并行、可以无人值守 —— 这**不算**抢跑。
- **展示效果**必须由学生的输入触发 —— 学生没说，画面上就不该出现 A 组的第一个问题。

## 2.6 不剧透（硬约束）：一步一步来，后面几步的结果不许提前出现

**一次只推进一幕。** 每一步只输出当前这一步该出现的画面、动作、结论。

| 属于哪一幕 | 不许提前出现 |
|---|---|
| 第 2 幕 | `requirements.spec.md`、A 组任何一道题 |
| 第 3 幕 | 症状数值（下沉 fpm / 过载 / 坡度峰峰）、`act3-*` 截图与 CSV、C 组答案 |
| 第 4 幕 | 保护 / 降级 / 参照机的截图与 CSV、试飞结论 |

**“演示前准备”（允许）与“展示准备结果”（禁止）是两件事**：

- ✅ **动作**可以提前：起服务、装补丁、跑症状回归、预热 WASM、校验时间轴、建产出目录、预加载页面。
- ❌ **输出**不得展示：症状回归的表格是**第 3 幕的结论**；时间轴校验通过说明的是**第 3、4 幕的脚本**；
  提前截的图属于后面某一幕。汇报准备状态时只说“准备就绪”，**不列数字、不贴表、不提前给截图**。

**也不得提前生成后续幕的产出物**：第 2 幕还没开始，就不该有 `requirements.spec.md`；
第 3 幕还没走到，就不该有 `act3-*` 的截图或 CSV。

> **为什么**：观众看的是“一步一步长出来”。任何提前出现的后续结果，都会让当前这一步失去意义 ——
> 你还没问，答案已经在了。这与“后台跑完再汇报”是同一个毛病的两种表现：
> 一个是把**全部**结果提前给，一个是把**下一步**的结果提前给。

**每一步结束时**：只交代这一步发生了什么、看到了什么，**不预告下一步会看到什么**。

## 3. `demo_driver.mjs` 的正确用法

`demo_driver.mjs` 是**提词单**，不是**替身**：

- ✅ **可以**：演示**前**用 `--dry` 校验时间轴结构（不启浏览器），再跑 `verify_noaero.mjs` 验症状、把页面预热一遍。
- ✅ **可以**：演示**中**用它驱动一个 **headed** 浏览器，展示人在旁边讲，随时接管（按 `Enter` 推进）。
- ❌ **不可以**：任何“跳过暂停、一路跑完”的用法。驱动**没有** `--no-pause` 之类的无人值守模式；
  一旦接管接不上（stdin 关闭、非交互终端），它会**报错退出**，而不是替你继续。
- ❌ **不可以**：`--headless` 跑完，把 `run.log` 和产出物贴出来当"演示完成"。

> 判断标准很简单：**观众有没有看到画面？** 没看到，就是没演。
>
> “让脚本自动跑完”这个念头本身就是要防的东西：四幕的教学价值全在**暂停点**上
> （第 2 幕的学生作答、第 3 幕 3.2/3.3 的指出问题与选择题）。把暂停点跳过，
> 剩下的就只是切页面 + 按按键，产出一堆文件也证明不了任何教学发生过。

## 4. 推荐的执行骨架（内置浏览器）

```
第 1 幕   note/讲解（平台入口不在 fcs-demo 控制范围内）
第 2 幕   平台提问 → 停下等学生作答 → 判定 → 追问/进下一题 → 收敛 → 写 requirements.spec.md
          （浏览器侧：load ?aero=1，截"界面可用"图）
第 3 幕   3.1 load ?aero=0 → 截图 → 松手等 10 秒 → 再截图（症状可见）
          3.2 逐条追问症状（B 组），问到 B8
          3.3 把题面念给观众 → 停下等学生选
          3.4 切 ?aero=1 → 截图 → 沉默 5~10 秒
          3.5 两版各导 CSV，并排看"升降率"
第 4 幕   真实按键/点击：拉杆 → 满杆到底看保护 → 预设 alpha → 预设 ahrs
          → 按 V 看参照机 → 导出 CSV；每一步都截图
```

## 5. 反例（做过这些就等于没演）

- 在后台 `--headless` 跑完，然后说"四幕已跑通，产出物如下"。
- 用 `--no-pause`（或把 stdin 接到 `/dev/null`、把脚本塞进非交互环境）让时间轴一路跑完，
  然后说"四幕已演完"。这条与上一条等价 —— **跳过暂停点 = 没演**。
- 在第 2 幕还没开始时就贴出症状回归的表格、时间轴校验输出，或第 3/4 幕的截图与 CSV。
- 把演示前准备的结果当成进度汇报（"症状回归通过：下沉 −1680 fpm……"）—— 那是**第 3 幕的结论**。
- 当前这一步还没走完，就先说"下一步我们会看到……"。
- 用 `evaluate` 直接 `app.fcs.setLaw("DIRECT")`，然后说"演了 AHRS 失效降级"。
  （正确做法：点/选"场景预设 → AHRS 失效"，让**应用自己**降级并写日志。）
- 平台自己把 A 组 12 问连同"标准答案"一次列完，然后说"学生答完了"。
- 只交付一堆 `.png` / `.csv`，没有任何一步是观众当场看见的。
