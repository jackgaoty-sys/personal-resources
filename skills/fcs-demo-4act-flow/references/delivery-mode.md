# 执行方式（硬要求）：必须"看得见地"演一遍

> **这份文件是给"平台"（Agent）看的，优先级高于本 Skill 里任何"怎么跑脚本"的说明。**
> 目的：杜绝"后台跑完脚本 → 汇报一堆产出物"这种**假演示**。

---

## 1. 一句话

**本 Skill 的交付物是"当场演一遍"，不是"脚本跑通了"。**

四幕是**教学演示**，观众要看的是"从零长出来的过程"。
把 `demo_driver.mjs --headless` 在后台跑一遍，再把 `demo-artifacts/` 列出来，
**不构成演示** —— 那是冒烟测试，观众什么都没看到。

> 驱动脚本也**没有**“跳过暂停、一路跑完”的模式（`--no-pause` 已移除）。
> 暂停点接不上真人时，脚本会**直接报错退出**，而不是替你继续。

## 2. 硬要求

| # | 要求 | 判定标准 |
|---|---|---|
| D0 | **触发闸门** | **只有学生用自己的话说出与“飞控系统”相关的需求后**，才能进第 2 幕引导与后续各幕；后端可提前准备，但**展示推进必须由学生触发** |
| D1 | **在看得见的浏览器里演** | 全程用 Codar **内置浏览器**（`in_app_browser_navigate` / `interact` / `evaluate` / `wait`）操作**真实运行的应用**，画面当场可见 |

| D3 | **真交互，不糊弄** | 第 4 幕的保护触发、故障注入、法则降级、参照机、导出 CSV，都用**真实 UI 操作**（点真实按钮、派发真实 `keydown`/`keyup`）；不得"直接改内部状态然后说演过了" |
| D4 | **不静默** | 禁止"后台跑完再汇报"。允许后台运行的只有**演示前的冒烟自检**（`--dry` 校验时间轴 + 症状回归 + 预热页面），**不含**跑整条时间轴 |
| D5 | **把戏交给真人** | 第 2 幕的学生作答、第 3 幕 3.3 的选择题，**必须停下等真人**；平台不得自问自答、不得代答、不得给台词（见 `platform-guidance.md`） |
| D6 | **逐步解说** | 每一步都要有【对观众】的话（见 `presenter-script.md`）；3.1 与 3.4 的"沉默 10 秒"是设计的一部分，要真的留出来 |
| D7 | **不剧透** | **一次只给当前这一步的东西。** 后续幕的 CSV / 断言结果 / 症状数值 / 结论，**一个字都不提前出现**；也不得提前生成后续幕的产出物。演示前准备可以做，但**准备动作的输出不得展示** |
| D8 | **内置浏览器独占** | 演示的**全部动作**都通过 Codar **内置浏览器**（`in_app_browser_*`）触发：导航、按键、点击、注入故障、导出。**不得**用独立窗口的 Playwright（`demo_driver.mjs`）来“演”—— 观众看的是 Codar 里的画面，独立窗口不算 |
| D9 | **不询问演示方式** | **不得**就“怎么演”向用户征求选择（现场真演 / 后台跑 / 代演学生 / 要不要截图）。**唯一形态是真演**；准备就绪直接开演，不回头问流程问题。见 §2.8 |
| D10 | **截图非必需** | 演示**不要求截图**。成立标准是“观众有没有看到画面”（D1/D8），不是“留下了几张图”。CSV 导出仍可作**可选证据**。见 §2.9 |

## 2.5 触发闸门（硬约束）：没听到“飞控系统”，就不许往下走

**第 2 幕的引导问答，只有在学生用自己的话说出与“飞控系统”相关的需求之后，才可以开始。**

| 允许（后台准备） | 禁止（展示抢跑） |
|---|---|
| 提前起 dev server、装气动开关、跑症状回归、预热 WASM、校验时间轴、建产出目录、预加载页面 | 学生开口之前，**抛出 A 组任何一道题** |
| 把舞台交给学生：“你想做的东西，用一句话说说看？” | 平台**替学生说**那句需求（哪怕只是“举个例子”） |
| 触发之后：按 A 组**一次一问** | 触发之前就推进到第 3 幕 / 第 4 幕 |

**判定（平台内部，不念给学生）**：学生的输入指向“做一个飞行控制系统 / 飞控 / 飞机控制系统 /
让飞机自己保持稳定”这一类意图，即视为触发。答非所问（例如“我想做个网站”）→ 平台**引导或追问**，
不要直接进 A 组。

> **为什么卡这么死**：这一幕的教学价值全在“学生先说了什么、平台才动”。
> 平台抢跑（或替学生说），观众立刻看出是背稿，“从零长出来”就没了。

**必须分清两件事**：

- **后端准备**可以提前、可以并行、可以无人值守 —— 这**不算**抢跑。
- **展示效果**必须由学生的输入触发 —— 学生没说，画面上就不该出现 A 组的第一个问题。

## 2.6 不剧透（硬约束）：一步一步来，后面几步的结果不许提前出现

**一次只推进一幕。** 每一步只输出当前这一步该出现的画面、动作、结论。

| 属于哪一幕 | 不许提前出现 |
|---|---|
| 第 2 幕 | `requirements.spec.md`、A 组任何一道题 |
| 第 3 幕 | 症状数值（下沉 fpm / 过载 / 坡度峰峰）、`act3-*` 截图与 CSV、C 组答案 |
| 第 4 幕 | 保护 / 降级 / 参照机的截图与 CSV、试飞结论 |

**“演示前准备”（允许）与“展示准备结果”（禁止）是两件事**：

- ✅ **动作**可以提前：起服务、装补丁、跑症状回归、预热 WASM、校验时间轴、建产出目录、预加载页面。
- ❌ **输出**不得展示：症状回归的表格是**第 3 幕的结论**；时间轴校验通过说明的是**第 3、4 幕的脚本**；
  后续幕的结论与产出物不得提前出现。汇报准备状态时只说“准备就绪”，**不列数字、不贴表**。

**也不得提前生成后续幕的产出物**：第 2 幕还没开始，就不该有 `requirements.spec.md`；
第 3 幕还没走到，就不该有 `act3-*` 的截图或 CSV。

> **为什么**：观众看的是“一步一步长出来”。任何提前出现的后续结果，都会让当前这一步失去意义 ——
> 你还没问，答案已经在了。这与“后台跑完再汇报”是同一个毛病的两种表现：
> 一个是把**全部**结果提前给，一个是把**下一步**的结果提前给。

**每一步结束时**：只交代这一步发生了什么、看到了什么，**不预告下一步会看到什么**。

## 2.7 内置浏览器独占（硬约束）：演示只能在 Codar 的内置浏览器里发生

**演示的每一个动作，都必须在观众正看着的那个内置浏览器里触发。**

| 动作 | 用什么 |
|---|---|
| 切页面（`?aero=0` / `?aero=1`） | `in_app_browser_navigate` |
| 按键（`W/S`、`R`、`V`、`Space`…） | `in_app_browser_interact`（`press`）或 `in_app_browser_evaluate` 派发 `keydown`/`keyup` |
| 点按钮（顶栏“气动”、`导出 CSV`、场景预设） | `in_app_browser_interact`（`click` / `select`） |
| 读状态、查断言 | `in_app_browser_evaluate` |
| 截图 | `in_app_browser_screenshot` |

**禁止**：

- ❌ 用 `demo_driver.mjs` 启动一个**独立窗口**的 Chromium 来演 —— 那是另一个窗口，观众没在看它。
- ❌ 在页面外“直接改内部状态”然后说演过了（见 D3）。
- ❌ 把时间轴的 `expect` 当成“演示时会自动跑”—— 断言要在内置浏览器里**当场求值**。

**`demo_driver.mjs` 的新定位**：只剩两个用途 —— ① 当**提词单**读（把“该按什么”固化下来）；
② `--dry` **校验时间轴结构**（不启浏览器）。它**不再承担演示执行**，已拒绝非 `--dry` 的调用。

**时间轴的 `expect` 怎么办**：演示时用 `in_app_browser_evaluate` 逐条当场求值，
把结果念进【对观众】的解说里。时间轴不再是“脚本自动跑”，而是**逐条检查表**。

## 2.8 不询问演示方式（硬约束）：默认且唯一形态是真演

**不要问用户“这次怎么演”。** 也不要在开场问“要不要开始 / 要不要截图”。
本 Skill 只有一种执行形态：**在 Codar 内置浏览器里逐幕真演**。

| 禁止的提问 | 为什么 |
|---|---|
| “你当学生现场演，还是我自动跑一遍？” | 把“是否真演”变成了可选项，等于承认假演也是合法路径 |
| “要不要截图 / 要不要留证据？” | 截图不是演示的成立条件（见 §2.9），问了只会拖时间 |
| “现在开始第 1 幕吗？” | 演示的开始由学生说出需求触发（D0），不是由平台征求许可 |

平台该做的：**准备就绪后直接开演**。该停的地方只有两个 —— 学生作答（D5）与选择题（D5），
其余一律推进，不再回头问流程问题。

## 2.9 截图非必需（硬约束）：看到画面即成立

**本 Skill 不要求截图。** 演示的成立标准是 D1/D8：观众在**内置浏览器**里**当场看到**了画面。

- ❌ 不必为每一幕留 `actN-*.png`；也不必在汇报里列截图清单。
- ✅ 仍然禁止的是“没演就汇报”（D4），**不是**“没截图就汇报”。
- ✅ CSV 导出（第 3 幕对照、第 4 幕归档）仍可做，属于**可选证据**，不是演示要件。

> 判断标准一句话：**观众看到画面 = 演了**；有没有 `.png` 不影响这个判断。

## 3. `demo_driver.mjs` 的正确用法

**它不再是演示的执行器。** 演示只能在内置浏览器里发生（D8）。

- ✅ **可以**：用 `--dry` 校验时间轴结构（不启浏览器）—— 这是演示前的准备动作。
- ✅ **可以**：把它当**提词单**读，知道这一幕该按什么、该看什么、该断言什么。
- ❌ **不可以**：用它驱动浏览器来“演”。它的浏览器模式已停用；非 `--dry` 调用会直接报错退出。
- ❌ **不可以**：`--headless` 跑完，把 `run.log` 和产出物贴出来当“演示完成”。

> 判断标准很简单：**观众有没有看到画面？** 没看到，就是没演。
> 而且这个“画面”指的是 **Codar 内置浏览器**里的画面 —— 独立窗口不算。
>
> “让脚本自动跑完”这个念头本身就是要防的东西：四幕的教学价值全在**暂停点**上
> （第 2 幕的学生作答、第 3 幕 3.2/3.3 的指出问题与选择题）。把暂停点跳过，
> 剩下的就只是切页面 + 按按键，产出一堆文件也证明不了任何教学发生过。

## 4. 推荐的执行骨架（内置浏览器）

```
第 1 幕   note/讲解（平台入口不在 fcs-demo 控制范围内）
第 2 幕   平台提问 → 停下等学生作答 → 判定 → 追问/进下一题 → 收敛 → 写 requirements.spec.md
          （浏览器侧：load ?aero=1，让“界面可用”当场可见）
第 3 幕   3.1 load ?aero=0 → 松手等 10 秒（症状当场可见）
          3.2 逐条追问症状（B 组），问到 B8
          3.3 把题面念给观众 → 停下等学生选
          3.4 切 ?aero=1 → 沉默 5~10 秒
          3.5 两版各导 CSV（可选），并排看“升降率”
第 4 幕   真实按键/点击：拉杆 → 满杆到底看保护 → 预设 alpha → 预设 ahrs
          → 按 V 看参照机 → 导出 CSV
```

## 5. 反例（做过这些就等于没演）

- 在后台 `--headless` 跑完，然后说"四幕已跑通，产出物如下"。
- 开场先问用户“这次怎么演 / 要不要截图 / 要不要开始”，把“是否真演”变成了可选项。
- 用 `--no-pause`（或把 stdin 接到 `/dev/null`、把脚本塞进非交互环境）让时间轴一路跑完，
  然后说"四幕已演完"。这条与上一条等价 —— **跳过暂停点 = 没演**。
- 在第 2 幕还没开始时就贴出症状回归的表格、时间轴校验输出，或第 3/4 幕的截图与 CSV。
- 把演示前准备的结果当成进度汇报（"症状回归通过：下沉 −1680 fpm……"）—— 那是**第 3 幕的结论**。
- 当前这一步还没走完，就先说"下一步我们会看到……"。
- 用 `demo_driver.mjs` 起一个**独立窗口**的 Chromium 把四幕跑完，然后说"演完了" ——
  观众看的是 Codar 里那个窗口，独立窗口里的画面他们没看到。
- 用 `evaluate` 直接 `app.fcs.setLaw("DIRECT")`，然后说"演了 AHRS 失效降级"。
  （正确做法：点/选"场景预设 → AHRS 失效"，让**应用自己**降级并写日志。）
- 平台自己把 A 组 12 问连同"标准答案"一次列完，然后说"学生答完了"。
- 只交付一堆 `.png` / `.csv`，没有任何一步是观众当场看见的。
