## 结论

脱离 HTTP 请求后续跑的定时任务、审批恢复和 Sandbox 后台唤醒，必须根据持久化的 owner user/session 重建租户 Provider 权限，不得回退到进程全局 Provider。

## 适用场景

- 任务创建与模型调用发生在不同请求或进程周期。
- 一个 Agent 服务同时服务多个用户，每个用户拥有独立的模型凭据。

## 方法

1. 创建任务时持久化 owner user_id、公开 session_id 及租户私有 Agent session 映射。
2. 后台执行前根据 user_id 读取当前有效的租户身份与 Provider 凭据。
3. 把 Provider 以请求或执行 context override 注入，避免替换全局 Agent 配置。
4. 续跑结果只回写 owner 的 SQL 会话和消息。
5. 租户凭据缺失、过期或校验失败时，保留可恢复状态或记录明确错误，禁止使用全局默认凭据继续。

## 边界与反例

- 不能假设后台 goroutine 仍持有创建它的 HTTP context。
- “有一个可用的全局 Provider”不是降级理由，因为它会造成计费、数据和会话归属错乱。

## 验证记录

- 2026-09-11：双租户定时任务分别观测到所属用户的 Provider Token；故意使租户 Provider 失效时未回退全局 Provider。
